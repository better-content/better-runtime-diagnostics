# Runtime diagnostics: playtest qualification inventory

Authoring inventory, **not an execution receipt**. No tests or native sessions were run for this document. This repository's principal shipped promise is bounded, opt-in `BC_PLAYTEST schema=bc.playtest.v1` diagnostic output and explicit source identity from its **own** mod metadata, alongside operator-triggered export/snapshot and Debug-world observation. Diagnostic output must not affect gameplay or claim native multiplayer success by itself.

## Existing local coverage and invocation boundaries

- `src/test/java/.../diagnostics/PlaytestLogContractTest.java`: pure sink/clock tests of disabled lazy detail, single status, burst/refill, summary suppression and cardinality, escaping/record length, focused TRACE lifetime, metadata origin and concurrent producer budget. `PlaytestLogQualificationTest.java` adds rollover without a false summary, duplicate status and malformed-event single-line checks. `ExportOutcomeTest`, `RuntimeSnapshotWriterTest`, `RecipeGraphExporterTest`, `CombatArmorCanonTest`, and `DimensionRegistryEvidenceTest` protect pure result/snapshot/export behavior. `FixtureClientInputTest`, `FreshWorldInputTest`, `VerifyWorldExitRequestTest`, `WhaleObservationTest` and `DiagnosticSupportBoundaryTest` cover narrow input/support boundaries. These are source-level checks, not evidence of a running pack or actual player joins.
- `./gradlew test` runs repository unit tests; **do not invoke without separate human test-run approval**. `./gradlew testSupportJar` builds a nonshipping support archive; `./gradlew verifyTestSupportIsolation` additionally inspects production/support archive separation and observer bytecode; both are build/verification operations, not authorized by this authoring task. `stageRuntimeJar` stages the production archive; `assemble` depends on it. Avoid invoking Gradle here: no builds, tests, packaging or deployment were authorized.
- Production `PlaytestDiagnostics` emits status on common setup, summary at server/client END tick only when enabled, and resets at server stop/client logout; `PlaytestLog` retains no world/player objects, caps aggregation keys at 256, records at 2048 characters, burst at 20, detail refill at 120/minute, and focused TRACE at one minute/1000 records. `RecipeGraphCommands` exposes operator export and geometry probing. `RuntimeSnapshotWriter` binds document identity and removes stale completion markers on failure. Local tests cannot prove the native lifecycle bridge fires under a dedicated server or client.
- Existing `src/testSupport/` includes `FreshWorldProbe` and `DedicatedOnboardingProbe` for fresh Debug-world and dedicated onboarding; `ObservedCampaignPresenceProbe` for real online tick intervals and offline exclusion (separate from `CampaignPresenceFixture`, which **authors history** and cannot prove elapsed online time); `DeepVoidTickProbe` for before/after native END player tick; gameplay world/client, recipe/EMI, colony, lifecycle, structure loot, whale and other observational probes. Some fixtures intentionally create/position state to exercise native paths: distinguish their setup from passive observation. The support artifact is never the production diagnostic JAR. `verifyTestSupportIsolation` checks configured mixin observers and prevents support classes in production; do not add a mixin or broad GameTest driver without revisiting that allowlist and native behavior.

## Required acceptance evidence still missing

1. **Exact artifact and native lifecycle:** record production/support JAR hashes, pack/client/server artifact identity, run ID, world identity, timestamps, Java version, process IDs and termination; on dedicated server and actual connected client verify exactly one startup status per process, source metadata corresponds to the owning JAR, client/server summary/reset boundaries, and no disabled DEBUG/TRACE detail. A pure sink test or Forge fixture is not real-login proof. Preserve logs and case-scoped receipts with start/end, status (`passed`/`failed`/`not_run`), reason and pointers to raw lines; fail closed on missing or mismatched evidence.
2. **Failure isolation:** deliberate malformed/absent own-source metadata returns `UNKNOWN` rather than another JAR's commit; disabled logging does not evaluate expensive suppliers; flood of 257+ distinct keys and concurrent producers remains bounded, summaries retain attempted/emitted/suppressed/overflow; logout/reconnect does not rearm the budget or TRACE; malformed focus produces a single notice and no detail. Pure variants are present, native log-level wiring and sustained server behavior remain unproven.
3. **Scale / fake players:** no implemented fake-player conformance harness exists in this repository. Target separate cohorts of **8, 16, 32**, at production simulation/view distance **10**, with **distinct actually ticking chunks** (not 32 players standing in one spawn chunk). An eventual nonshipping driver must prove each simulated player is a registered, living Survival `ServerPlayer`, distinct UUID and chunk, loaded/ticking per-player chunks over a measured interval, continuously advancing real server/world ticks, and record per-cohort tick durations/TPS, memory/GC, exceptions, save/reload and clean removal. Reject unloaded or merely ticketed chunks and unconfirmed player ticks. Establish a baseline of the same world/pack with zero simulated players, per-cohort warm-up and comparable observation windows; retain raw tick and chunk evidence. Fake players do **not** demonstrate real network login, client rendering/input, multiplayer transport, or all mod integrations; separately qualify 2+ real connected clients and reconnect/world continuity. Do not use observational hooks that mutate native state or gameplay to manufacture a passing result.
4. **Exports and continuity:** a native operator export should prove schema, completion, consistent snapshot identity, all declared documents and hashes, bounded error response and no prior completion marker after failure. Compare fresh and restarted persistent world; observe the actual playtest's save/no-reset policy. Pure snapshot tests do not constitute a complete world-export or save-integrity receipt.

No new fake-player driver or receipt emitter was added here: neither a reliable ticking-chunk conformance API nor an authorized native execution path is established by the inspected support sources. A validator without a genuine observer would risk a placeholder passing probe. The pack-level qualification runner must mark these missing native cases `not_run`, not `passed`, until the corresponding case-scoped raw evidence and approval exist. This inventory does not authorize running any tests or altering gameplay.
